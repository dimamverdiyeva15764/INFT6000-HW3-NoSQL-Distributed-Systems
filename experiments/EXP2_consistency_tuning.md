# Experiment 2 — Consistency Tuning (ONE / QUORUM / ALL)

Owner: Person 2 · Plots: generated by `workload/exp2_summary.py` (Person 4's `analysis/`
pipeline can consume the same CSVs) · Report: §3 and §7.2

## Goal

Measure how the consistency level changes **latency**, **throughput** and **data
freshness** on a healthy 3-node cluster with RF = 3, and relate the results to the
quorum condition R + W > N.

With N = RF = 3 and QUORUM = ⌊3/2⌋ + 1 = 2:

| Write CL (W) | Read CL (R) | R + W | R + W > N? | Nodes that may fail and still serve both ops |
|---|---|---|---|---|
| ONE (1) | ONE (1) | 2 | No — stale reads possible | 2 |
| ONE (1) | QUORUM (2) | 3 | No | writes 2, reads 1 |
| QUORUM (2) | QUORUM (2) | 4 | Yes | 1 |
| ALL (3) | ONE (1) | 4 | Yes | writes 0, reads 2 |
| ONE (1) | ALL (3) | 4 | Yes | writes 2, reads 0 |

## Prerequisites

```bash
make up && make schema && make smoke     # 3 x UN, keyspace chat, smoke PASS
make test                                # unit tests green (no cluster needed)
```

Close other heavy applications: all three nodes and the client share one machine.

## Procedure

```bash
make exp2-quick    # optional ~4-minute dry run (1 repetition, 10-s runs)
make exp2          # full grid, about 40 minutes
make exp2-report   # (re)build tables, figures and report numbers from the CSVs
```

`workload/consistency_matrix.sh` runs every step through the client container:

| Step | Runs | Parameters |
|---|---|---|
| 1. Preload | 1 | 10,000 messages into 100 rooms (partitions) at QUORUM, so reads return data |
| 2. Fixed-rate grid | 3 modes × 3 CLs × 3 reps = 27 | open loop, 200 ops/s, 8 threads, 60 s measured after a 10-s warm-up that is not logged; the CL order rotates per repetition |
| 3. Saturation | 3 (one per CL) | closed loop (`--max`), 32 threads, mixed 50/50, 30 s after 5 s warm-up |
| 4. Freshness probes | 5 pairs × 3 reps = 15 | 2,000 probes each, 4 threads; write `room_state.last_seq = n` via coordinator A, read it back immediately via coordinator B ≠ A; `stale = 1` if the read returned less than `n` |
| 5. Summary | — | `workload/exp2_summary.py` |

Every parameter can be overridden: `RATE=300 REPS=5 make exp2` (see
`bash workload/consistency_matrix.sh --help`).

Single runs, e.g. for a re-run of one cell:

```bash
docker compose run --rm client python -m workload.runner --exp exp2 --mode read --cl ALL \
  --rate 200 --threads 8 --duration 60 --warmup 10 --variant read --rep 2
docker compose run --rm client python -m workload.runner --exp exp2 --mode probe \
  --write-cl ONE --read-cl ONE --probes 2000 --threads 4 --variant probe --rep 1
```

## Expected results (qualitative — report what you actually measure)

- **Latency** ordered ONE ≤ QUORUM ≤ ALL: the coordinator waits for 1, 2 or 3 replica
  responses. On one host the replica round trip is sub-millisecond, so the gap may be
  small; the p99 gap is usually larger than the p50 gap because ALL waits for the
  slowest replica.
- **Throughput** at the fixed rate equals the target (200 ops/s) for every CL; the
  closed-loop runs show the saturation point. With RF = N = 3 every replica applies
  every write whatever the CL, so write cost on the servers is the same.
- **Staleness** is only *possible* for pairs with R + W ≤ N (ONE/ONE, ONE/QUORUM). On a
  healthy local cluster it is rare or zero, because replication finishes faster than
  the client's next round trip. It becomes clearly visible in Exp 4b and Exp 5, when a
  replica has missed writes.
- **No errors** on a healthy cluster. Any error is a finding (check `docker_stats.csv`).

## Failure conditions and recovery

| Symptom | Cause | Recovery |
|---|---|---|
| `WARNING: … operations started >50 ms late` | all threads busy (host overloaded) | lower `RATE` or raise `THREADS`; close other apps; rerun that cell |
| CPU near 100 % in `docker_stats.csv` | host saturation distorts latency | lower `RATE`, give Docker more CPUs |
| A run exits with code 3 | no operation succeeded (cluster not healthy) | `make status`; `make smoke`; rerun |
| `read` runs warn "reads returned no rows" | preload missing | rerun `make exp2` (preload is step 1) |
| `exp2-report` says "no Experiment 2 data" | no CSVs yet | run `make exp2` first |
| `ModuleNotFoundError: pandas` | old client image | `make client` (rebuilds with the new requirements) |

Hidden retries are impossible by construction: `app/db.py` uses
`FallthroughRetryPolicy` and no speculative execution, so every failure is logged.
